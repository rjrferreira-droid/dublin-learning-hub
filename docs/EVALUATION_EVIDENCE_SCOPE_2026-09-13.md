# Evidence-backed evaluation candidate — scope

Continue PR#3 without routine approval prompts, with a short final summary. This tranche addresses two inspected evaluator issues: permissive score/confidence coercion and absence of a check that quoted error examples came from the learner. It also exposes recorded examples/confidence in the existing feedback UI, using the same read.

The candidate worker requires indexed verbatim learner citations for retained numeric scores and error examples. Teacher/reference text, unsupported quotations, obvious help-only turns, interrupted/truncated turns and acoustic judgments from text are rejected. Missing evidence becomes null, not zero. Confidence is explicitly numeric0–100, without coercing booleans/strings or multiplying a fractional percentage by100. Recorded error patterns are deduplicated and retain actual source snippets. Review is based on retained evidence, not truthiness of an arbitrary field. Transcript numbering encodes speech as JSON strings to avoid forged lines being interpreted as indexed turns.

Quote presence is necessary but does NOT prove that the inferred diagnosis, score, explanation, summary or rubric is correct. The rule conservatively excludes truncated/interrupted evidence; it can discard useful material. A narrow help-only matcher is not a general intent detector. Guidance about self-correction, valid alternatives and separating language/technical skill remains a model instruction, not a semantic guarantee. The model itself is not benchmarked by a fake response test.

The completion contract remains unchanged, including its accepted output fields. Turn-level citations gate the candidate assessment internally but are not persisted as a new provenance schema. The frontend calls stored excerpts 'examples stored with the assessment' and explicitly does not claim independent verification. Confidence is labelled as the evaluator's confidence, not mastery or a calibrated probability. Legacy results are not changed or automatically re-evaluated. Transcript-only pronunciation/fluency claims are not presented in the new details panel.

Only evaluation.ts plus the new evidence module are allowed worker-source changes. The published worker, model/pricing, budget, voice, dispatch, shutdown, Supabase, auth and all deployment workflows stay untouched. Feature Preview deployment cannot activate the candidate worker logic: it needs a separately reviewed LiveKit publication. A successful build is not that publication. No production merge, real credentials, paid requests, new keys, live voice or historical SQL export.

Tests use synthetic transcript/output pairs and fake provider transport, never actual user speech. They include compatibility with the unchanged completion sanitizer, one-call/no-retry behaviour, no raw provider-body logging, exact200wrong-identity handling already in the outcome service, safe escaped UI strings and mobile/desktop layout. Record success only after execution.

Primary references checked: OpenAI Structured Outputs (https://developers.openai.com/api/docs/guides/structured-outputs) notes that schema conformance does not guarantee correct values; React common components (https://react.dev/reference/react-dom/components/common) documents the risks of raw HTML injection. The display uses ordinary escaped React text, not injected HTML. These references do not certify our model or our safeguards.
