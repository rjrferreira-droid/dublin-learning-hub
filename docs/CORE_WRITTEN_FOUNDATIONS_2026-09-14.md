## Runtime and provider boundary

`remainingWrittenRegistry.ts` identifies exact per-track slugs and sequences. The lightweight loader opens one sequence's authored module chunk only when needed. It preserves the catalog UUID and rejects malformed IDs, cross-track slugs, draft/registry mismatches and invalid visual/hint shape. The existing published catalog remains the only source of real catalog rows. No row is created or published.

`quality/candidates/remaining-professor-reference.ts` prepares bounded, source-hashed **offline** references for sequences 5–8. It checks assigned adult profile, requested track and ID, exact lesson/module/course joins, all publication/active flags, slug/sequence and positive content version. It explicitly constructs context from authored fields, omitting extra browser fields and checkpoint results. Changing content version changes the hash. The caller must eventually resolve the chain through authenticated server reads; caller-supplied booleans are not a deployed authorization boundary.

No live API imports this candidate. It does not start a session, reserve budget or authorize a provider. P1 live Preview resolution, Professor/evaluator/Audio admission registries, Supabase, frozen Auth and LiveKit remain unchanged. Integration of future interactive lessons still requires the existing exact identity/context-before-atomic-start flow and independent acceptance.
